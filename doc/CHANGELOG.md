# 更新日志

本文件记录面向使用者的重要变化。版本内容依据 Git 标签与提交历史整理。

## [未发布]

### 功能

- `.env` 不再强制要求 AM4 账号：`AM4_EMAIL`/`AM4_PASSWORD` 可留空，面板与 `/setup` 照常启动；只有启动某个账号的采集循环时才要求该账号凭据
- `/setup` 只创建纯管理账号，移除「接入 .env 游戏账号」；管理员不绑定任何游戏账号
- 注册页可选验证 AM4 账号：独立临时 Cookie 尝试游戏登录，仅验证不保存凭据，按 IP 限流

### 安全修复

- 实时推送（SSE）按账号路由：携带账号字段的事件只投递给该账号的订阅者，其他用户不再能收到他人的余额、机队与日志；`/api/status` 与流的运行列表对普通用户只返回自己账号
- SSE 同一会话只保留一条连接，连接上限默认降为 8（与 Gunicorn 线程数对齐），防止长连接占满工作线程导致面板不可用
- 首次初始化 `/setup` 必须携带 `.env` 中的 `AM4_SETUP_TOKEN`（未配置则网页初始化禁用），响应不再回显 `.env` 游戏邮箱
- 管理员改密、改状态、删除接口在后端拒绝管理员目标，管理员密码仅可由服务器配置修改
- AM4 游戏邮箱唯一绑定：按大小写/空白归一建立唯一索引并做注册查重，防止两个网站账户串到同一游戏账号
- `AM4_PROTECTED_ACCOUNTS` 覆盖在线建设与实时精算；管理员停用/删除网站账户时联动：立即停止其循环并把该游戏账号视为受保护，重新启用后自动恢复
- 登录接口补 CSRF 校验；磁盘全局 CSRF 令牌仅对回环请求生效，远端泄露也无法用于跨站写操作
- 注册限流增加用户名维度，并通过 `AM4_TRUST_PROXY` 还原真实客户端 IP，修复反代后按 IP 限流失效
- 航线预估/候选/排序、机场搜索与管理员模拟接口的数值参数改为 400 校验，不再因非法参数抛 500
- 账号设置清洗：布尔开关正确解析 `"false"` 等字符串，数值键增加上下界限制
- 注册用户名限制为 2~8 位英文字母或数字（可含空格、`_`、`/`，头尾不允许空格），从源头收紧审计日志注入与面板展示注入面；注册/初始化表单同步前端校验，`.env` 的 `AM4_ADMIN_USERNAME` 同样适用该规则并在配置示例与 README 中注明；面板顶部账号标签改为显示登录用户名（游戏邮箱保留在悬停提示）
- 生产默认关闭模板自动重载（`AM4_DEBUG_TEMPLATES=1` 可开），新增 `AM4_SETUP_TOKEN`、`AM4_TRUST_PROXY`、`AM4_MAX_SSE_CLIENTS`、`AM4_DEBUG_TEMPLATES` 环境变量与部署示例

### 测试

- 回归测试增至 182 项，覆盖账号路由、初始化令牌、管理员守卫、邮箱唯一、受保护账号与停用联动、登录 CSRF、用户名规则、审计日志防注入、邮箱绑定并发竞态、账号状态定向查询、纯管理员创建、无凭据启动防护与 AM4 账号验证等安全边界

## [2.3.1] - 2026-08-13

### 修复

- 登录与重新登录后必须重新读取主页验证登录状态，失败时明确报错，不再把“请求已发送”当作“登录成功”
- 营销购买响应丢失时改为有限退避后重试；游戏不允许同种营销重复购买，因此重试天然幂等，不会重复扣款，也不会因只读确认而永久中断
- 营销待办不再因没有航线 ID 而被误标为“航线未建”
- 改装或维修中的飞机待办统一显示为“返场结束后接管起飞”，并兼容已有旧标题
- 检修数据改为保存当前快照，已完成的历史检修不会继续残留在列表中
- 购机或建线已成功时，即使随后余额回读失败，也不会把成功操作误判成响应不明或进入重复写入恢复流程
- 营销页面无法确认时保持安全等待，不执行购买

### 界面与日志

- 机队注册号按状态显示颜色：飞行中绿色、已落地蓝色、返场中红色、建设中黄色
- 精简移动端较长的飞行接管、首航和资源采购日志，同时保留操作原因与预计时间
- 起飞失败待办改用短标题并将航线、原因和重试时间分行显示，避免移动端出现超长单行
- 待办接口显式区分是否需要航线，避免前端根据 `route_id` 猜测任务类型
- 新增飞机航路主题站点图标及 favicon、Apple Touch Icon、Web App Manifest 图标集
- 默认采用日间配色，并在首帧绘制前恢复主题，消除刷新时的深色闪烁
- 按账号缓存机队、枢纽、市场和检修概览，刷新后先恢复上次画面再静默同步实时数据
- 页面首屏直接复用服务器本地快照；浏览器缓存不可用或接口短暂为空时不再清空已有机队与枢纽
- 将浏览器缓存恢复前移到机队表格之后，不再等待整份页面下载完成才恢复已有画面
- 机队筛选、搜索与排序改为前端本地派生，不再重复请求接口或覆盖实时飞机颜色
- 优化移动端页眉、单行横向枢纽栏和机队表格：工具栏仅保留搜索，注册号不换行，枢纽名称可横向滚动
- 统一实时与历史日志的颜色判断：错误红色、成功绿色、`not_ready` 等待黄色、普通过程灰色

### 整理

- 主程序目录由 `work/` 更名为 `src/`，同步更新测试、文档与 systemd 配置
- 删除已完成的 TODO 和内部问题记录，补齐公开部署与安全说明
- 采用 CC BY-NC-SA 4.0，要求合理署名、非商业使用及衍生作品相同方式共享，但不限定署名格式；第三方 AM4Help 内容保留 MIT 许可声明
- 清理只验证源码字符串、与行为测试重复的脆弱用例，保留安全边界与异常恢复覆盖

### 机队状态

- 全量采集的逐架更新在前端原位替换，不再把飞机移动到列表末尾
- 增量飞机事件带上主页运行状态，飞行中或返场中的颜色不再临时回退为蓝色
- 识别主页 `grounded` 人工停飞状态：结束当前自动起飞待办，并在每日全量重新发现前保持停飞
- 主页状态刷新后通过 SSE 即时更新整支机队颜色；浏览器按预计落地或返场时间在本地自动切换状态，不增加游戏页面访问

## [2.3.0] - 2026-08-12

### 航线建设

- 新增 `Maximise` 班次：为每条候选从物理上限向下寻找可满载的最高班次，并据此计算布局和日净利
- 新购飞机在首笔写操作前写入机队表并标记“建设中”，避免半点采集覆盖目标枢纽和航线信息
- 改装提交后读取首页待定时间；游戏确认受理后按真实完成时间安排起飞
- 首航确认后完整刷新单机信息并清除建设状态，客机和货机共用完成链路
- 购机、建线和营销扣款成功后立即刷新余额，连续建设不再复用旧资金快照
- 确认飞机已售出时取消其交付、改装、首航和起飞待办，并关闭建设记录

### 调度与界面

- 广告 4 和环保营销改为按实际到期时间续排的持久待办，移除固定 00:00 / 12:00 槽位
- 打开日志页时自动滚动到最新内容
- 新增 Linux `curl`、Gunicorn、systemd 和 Nginx 部署支持

### 整理

- 采集器更名为 `collector.py`
- 机队主表更名为 `fleet.csv`，启动时自动迁移旧文件
- 回归测试增至 113 项

## [2.1.0] - 2026-08-09

### 自动运营

- 取消每四小时逐架扫描，改为每日全量发现与每架飞机持久待办接管
- 起飞和返场统一增加两分钟缓冲，在线失败采用 5/15/30 分钟有限退避
- 启动和轻量刷新复用已抓页面执行补货；燃油未知或不足时不访问飞机详情
- 首页可识别飞行、维护和改装中的飞机，并登记完成后的接管待办

### 航线建设

- 完整支持货机 L/H 需求、货舱、票价、购机接口和改装
- 多发动机机型从估算到购机、交付和待办全程绑定所选发动机
- 建设流程增加资金安全垫、参数校验、幂等恢复和详细步骤日志
- 改装成为起飞前置任务；失败不安排起飞，人工完成后可自动对账
- 修复已有航线恢复、机队 ID 丢失和建设参数持久化

### 一致性与安全

- 账号目录使用可读前缀与稳定哈希，待办、缓存、输出和 Cookie 按账号隔离
- 待办 JSON 与机队 CSV 原子写入，采集与服务端通过文件锁协调
- 轻量对账支持新增、改名和确认售出，前端增量遵守当前筛选
- 修复登录表单编码、交付查询失败误判、枢纽名称 DOM 注入和多种失败恢复路径
